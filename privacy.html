Sundanese96 AutoPoster Studio Privacy Policy

Last updated November 24, 2026

Sundanese96 maintains Sundanese96 AutoPoster Studio, a Windows desktop app for uploading and scheduling finished videos and retrieving performance data for authorized YouTube channels. The desktop app uses YouTube API Services. This policy explains what it collects or accesses, how it uses and stores that data, and how the operator can revoke access and delete records.

Google user data and why the app needs it

  • Google authorization. Google handles sign-in, passwords, and consent on its own pages. When the operator grants access, the desktop app receives an OAuth access token and refresh token. The app uses them to call the authorized YouTube APIs and renew access for later runs.
  • YouTube channel and video data. The app reads the connected channel’s ID, name, uploads playlist, and counts such as subscribers and views. It reads recent video IDs, titles, publication dates, and counts such as views, likes, and comments. The app uses this data to confirm which channel is connected, find recent uploads, and display channel and video status.
  • YouTube Analytics and Reporting. At the operator’s request, the app retrieves channel and video performance data, including watch time, average view duration, audience retention, subscriber changes, and aggregate viewer country. It can list or create a reporting job and download report data for the operator to inspect.

Files and settings supplied by the operator

The app reads the video, thumbnail, and metadata from the content folder the operator selects. For an upload, it sends the video, optional thumbnail, title, description, tags, category, language, audience and visibility settings, and any scheduled release time to YouTube. YouTube returns a video ID that the app uses to report success, build the video URL, and prevent duplicate uploads.

Storage, protection, and retention

The app communicates with Google and YouTube APIs over HTTPS. It saves tokens in per-channel JSON files in the operator’s configured project storage. Access to these files depends on the operator’s device and storage permissions. If those directories are synchronized, the sync provider can retain copies. The public website has no access to these files.

  • Credentials and settings. The app keeps each channel’s credential file and configuration in project storage for later runs. The channel title may be saved in that configuration.
  • Upload records. The app keeps an upload history and an upload status file in each processed content folder. Records can contain the channel label and title, video ID and URL, upload time, and local content path. The app keeps these records until the operator removes them. The quota tracker starts a new record when the app next runs on a new UTC date.
  • Analytics and report output. The app retrieves these results on demand and shows them in the terminal. The operator can save a copy of that output separately.

Who receives the data

Google receives authorization and token requests. YouTube receives the selected media, publishing settings, and channel, analytics, and report requests. YouTube controls access to uploaded videos according to the chosen visibility setting, including release to the public when the operator chooses public visibility. See the Google Privacy Policy.

Some runs check the public IP address and approximate country of the operator’s connection using IPinfo, ifconfig.me, or api.myip.com. Those services receive the network request and source IP address. The requests contain no Google user data, OAuth tokens, or media. The app can also start or stop the operator’s installed Windscribe VPN when enabled.

The desktop app uses Google user data for channel authorization, publishing, duplicate prevention, and reporting. The app does not sell that data, use it for advertising or AI training, or send it to the connection-check services. The public GitHub Pages site presents the app’s documentation and contains no sign-in form, upload form, or app analytics scripts.

Revoking access and deleting data

  1. Open Google Account permissions with the account that granted access, select Sundanese96 AutoPoster Studio, and remove its access.
  2. Stop any scheduled desktop runs for the disconnected channel. Remove the corresponding token file, channel configuration, upload-history entries, and upload status records from the desktop app’s storage. Remove any copies kept separately or in synced folders.
  3. To request help accessing or deleting stored app data, email the contact below. Identify the channel involved so the operator can locate its records.

Videos already uploaded remain in the YouTube channel. To manage or delete those videos, use YouTube Studio.
